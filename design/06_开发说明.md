# 06 开发说明

## 1. 技术框架建议
- 纯 HTML5 + 原生 JS（ES Modules）或 Phaser 3（二选一，推荐原生 Canvas/DOM 混合：背景/热点用 DOM 绝对定位层，特效用 Canvas）。
- 竖屏 1080×1920 逻辑分辨率，`contain` 缩放，letterbox 用 #1A1410；锁竖屏提示。
- 输入：仅点击/点按（不依赖拖动之外的手势；线索板连线用“点卡 A → 点卡 B”，同时支持拖动）。
- **数据驱动**：所有房间/道具/谜题/线索板/审讯/推理/心烛文本都来自 `data/chapter1.json`（策划已给出完整第一章数据，可直接用或作为模板）。
- 存档：`localStorage` 键 `hushwold_save_v1`，保存 {room, inventory, flags, evidence, sanity, cooldowns, solved}。每次状态变化自动存档。
- 目录建议：`/src/engine`（scene、inventory、dialogue、clueboard、interrogation、deduction、sanity）、`/src/data`、`/assets/img|audio`。

## 2. 通用约定
- **flags**：字符串布尔表，例如 `has_motto`、`crest_solved`、`cb_cycle_solved`。
- **条件 `req`**：`{ "items": [...], "flags": [...], "notFlags": [...], "evidence": [...] }`，四项全部满足才可触发（省略的项视为满足）。`evidence` = 手记里已收录的证据卡 id。
- **效果 `effects`**：数组，按顺序执行；13 种类型的正式定义见 **§10 效果类型参考**（与引擎 `logic.js runEffects` 字面一致）。
- **文本**：凡是“文本键”字段（`text.key`、审讯 `intro/text/onBreak.text/nearMiss`、推理 `q/hint`、`meta.endingTitle`、`cutsceneCaptions`）都填 `texts` 表里的键，键名格式 `^[a-z][a-z0-9]*(_[a-z0-9]+)+$`，缺键时引擎显示〔缺文本：key〕。以下字段是**直接显示的字面文本**（不查表）：道具 `name/desc`、证据 `name/desc`、线索卡 `label`、连线 `options`、推理 `options`、`note.add`、`fakeHotspots[].text`、`lowSanityReveals[].text`、热点 `label`。
- 房间导航：已解锁的房间之间可用底部左右箭头往返（R1⇄R2⇄R3），保证可回头取道具。
- 热点坐标用 1080×1920 逻辑像素矩形 `[x, y, w, h]`（占位，美术出图后微调）。

## 3. 房间与热点
```json
{
  "id": "r1_hall",
  "bg": "bg_r1_hall",
  "bgm": "bgm_r1_hall",
  "amb": "amb_hall_fire",
  "hotspots": [
    {
      "id": "h_table_under",
      "rect": [260, 1180, 420, 200],
      "interactions": [
        { "useItem": "candle_lit", "req": { "notFlags": ["got_rosary"] },
          "effects": [ {"type":"give","item":"rosary"}, {"type":"evidence","add":"ev_rosary"}, {"type":"flag","set":"got_rosary"} ] },
        { "default": true, "effects": [ {"type":"text","key":"t_too_dark"} ] }
      ]
    }
  ]

```
- `interactions` 按顺序匹配：先匹配 `useItem`（玩家选中道具点击热点），再匹配 `default`。

## 4. 道具与组合
```json
{ "items": { "rosary": { "name": "灰烛念珠", "icon": "item_rosary", "desc": "七颗灰珠，缺了那颗黑的。", "consumable": false } },
  "combine": [ { "a": "charcoal", "b": "scraper", "result": "charcoal_dust", "consume": ["charcoal"] } ] }
```
- **无死局规则**：关键工具 `consumable:false`；被消耗的道具一定已经完成全部用途（加载时用 `tools/verify` 脚本检查：每个 `useItem` 的道具在使用前都可获得）。

```json
  "intro": "t_ysolde_intro",
  "statements": [
    { "id": "s1", "text": "那位修士十一月就离开了，我亲自送他出门。", "portrait": "calm",
      "lie": true, "accept": ["ev_black_bead"],
      "nearMiss": { "ev_rosary": "t_ysolde_rosary_any" },
      "onBreak": { "text": "t_ysolde_break1", "portrait": "cold" } },
    { "id": "s2", "text": "莫尔德雷克家族从未失去过一个孩子。", "portrait": "calm",
      "lie": true, "accept": ["ev_revealed_tree", "ev_blank_coffins"],

    { "id": "s3", "text": "这口井干涸一百年了，只是个祈祷的地方。", "portrait": "cold",
      "lie": true, "accept": ["ev_wet_chain"],
      "onBreak": { "text": "t_ysolde_break3", "portrait": "shaken" } },
    { "id": "p1", "text": "你没有任何东西能证明是谁下的令。", "portrait": "cold",
      "lie": true, "accept": ["ev_seal_crozier"], "requires": ["s1","s2","s3"],
      "onBreak": { "text": "t_ysolde_confess", "portrait": "broken" } }
  ],
  "order": "free",
  "onWrongEvidence": [ {"type":"sanity","delta":-3}, {"type":"text","key":"t_wrong_evidence"} ],
  "onComplete": [ {"type":"evidence","add":"ev_confession"}, {"type":"flag","set":"int_ysolde_done"}, {"type":"sfx","id":"stinger_contradiction"} ]

```
- 流程：显示证词列表（已拆穿的盖“谎”字蜡印）→ 玩家选中一条证词 → 点“出示证据”→ 从手记证据中选一项。
- `accept` 命中 → onBreak；命中 `nearMiss` → 专属提示文本，不扣分；其他 → onWrongEvidence。
- `requires`：压迫类证词需前置证词都已拆穿才出现。
- 证据不足时（玩家尚未获得 accept 中任何证据）也允许出示，只会失败——但界面在证词旁显示“？”提示“我还缺一件证据”，引导回去搜证。

## 8. 心烛（Sanity）
```json
{
  "max": 100, "start": 100, "floor": 20, "chapterResetMin": 70,
  "tiers": [
    { "id": "s1", "min": 70, "fx": [] },
    { "id": "s2", "min": 40, "fx": ["fx_vignette_s2", "amb_whisper_low", "portrait_s2"] },
    { "id": "s3", "min": 20, "fx": ["fx_vignette_s3", "fx_ink_tendril", "amb_whisper_near", "portrait_s3", "text_glitch", "fake_hotspots"] }
  ],
  "restorePoints": {
    "r1_fire":    { "delta": 10, "cooldownSec": 60 },
    "r2_window":  { "delta": 10, "cooldownSec": 60 },
    "r3_candles": { "delta": 15, "cooldownSec": 60 }
  },
  "textGlitch": { "chance": 0.15, "protectKeys": true },
  "lowSanityReveals": [ { "room": "r2_scriptorium", "hotspot": "h_desk_original", "below": 40, "text": "1312 那一行的刮痕里，浮出半个字母：E。" } ],
  "fakeHotspots": { "r1_hall": [ { "rect": [120,1500,130,130], "text": "（字面文本）" } ] }
}
```
- `sanity = clamp(sanity + delta, floor, max)`；**永远不会触发失败**。
- `text_glitch`：随机替换非关键词为“▇▇”；`protectKeys:true` 时，标注为 `<k>…</k>` 的关键词不替换。
- `fake_hotspots`：每个房间 1–2 个，只在 s3 显示，点击仅出一句文本，不改变任何状态。
- 回复点由热点效果 `{"type":"restore","point":"r1_fire"}` 触发；道具回复写在 `items[id].use = { "sanity": 15, "cooldownSec": 90 }`（如 rosary_full），在手记道具页点“使用”，冷却键为 `item:<道具id>`。
- `once:true` 的扣减按 `hotspotId+effectIndex` 记录，防止重复扣。

## 9. 验证脚本（建议）
`tools/verify-chapter.mjs`：读取 chapter1.json，模拟“贪心可达性”搜索，确认：
1. 所有谜题都可解；2. 不存在消耗后不可再得的关键道具；3. 每个审讯的 accept 证据在审讯可用前都可获得；4. 所有文本 key 都存在。

## 10. 效果类型参考（v1.1 正式定义）
与引擎 `game/src/engine/logic.js` 的 `runEffects` 一致；“事件”指 runEffects 返回、由 UI 层消费的事件。

| type | 参数 | 行为（字面实现） |
|---|---|---|
| give | `item` | 不在背包则加入，发 `give` 事件；已有则无事发生 |
| take | `item` | 在背包则移除，发 `take` 事件 |
| flag | `set` 和/或 `clear` | `set` 置为 true；`clear` 删除该 flag（同一效果可同时写两者，先 set 后 clear） |
| evidence | `add` | 证据卡 id，未收录则加入手记证据页，发 `evidence` 事件 |
| sanity | `delta`，可选 `once` | 心烛 += delta，夹在 [floor, max]；`once:true` 时以 `来源#效果序号` 记一次，之后再触发跳过；发 `sanity` 事件（含实际 delta 与当前值） |
| restore | `point` | 查 `sanity.restorePoints[point]`（不存在则静默无效）。若冷却中：发 `{restore, ok:false, remain:剩余秒}`，UI 显示 uiText.restoreCooldown；否则冷却设为 now + `cooldownSec`（缺省 60）秒，发 `{restore, ok:true}`，再按该点 `delta` 改心烛 |
| text | `key` | 发 `text` 事件，文本 = texts[key]（缺键显示〔缺文本：key〕）；有模态窗时显示在模态窗内，否则在底部对白框 |
| note | `add` | **字面字符串**（不是文本键）；未记录过则追加到手记“笔记”页（去重），发 `note` 事件，UI 弹“记下：…”并给手记加角标 |
| goto | `room` | 切换到该房间（房间不存在则忽略）并记为已到访，发 `goto` 事件 |
| open | `ui`, `id` | 打开界面：`ui` ∈ `puzzle` / `interrogation` / `clueboard` / `deduction` / `notebook` / `item` / `closeup`；`id` 为对应数据 id（closeup 的 id 指向 json `closeups`，见 §12）。当前已有非手记模态窗时排队，关闭后再开 |
| sfx | `id` | 播放音效（05 清单里的 sfx_* id） |
| cutscene | `id` | 发 `cutscene` 事件，播放 `cutscenes[id]` 的图序列（配 `cutsceneCaptions[id]` 字幕）；若 `id === meta.ending`，同时置 `ended=true`，过场后进入结局页（标题 `meta.endingTitle`）。有模态窗时延后到关闭后播放 |
| hint | `mode` | 只在推理 `onWrong` 中有意义：发 `{hint, mode, question, text}`，`question` = 第一道答错题的序号，`text` = 该题 `hint` 文本键的内容，推理界面把它显示在该题下。当前只有 `mode:"firstWrong"`；在别处使用不会出错但无显示 |

未知 type 会产生 `unknown` 事件（verify 报错）。

**其他被 json 使用的类型/字段：**
- 谜题 `puzzles[id].type`：
  - `rotate_grid`（`size`、`initial`、`answer`：符号 id 数组，点格子顺时针换符号）；
  - `dial`（`digits`、`answer`：数字字符串；可选 `hintFlag`：该 flag 为真时在转盘下显示 uiText.dialHint，**只是提示，不锁输入**——要锁输入请用热点 `req`）；
  - `use_on_item`（`item`+`with`，在道具详情里用 A 道具对 B 道具）。
  - 所有谜题都有 `onSolved` 效果数组，v1.1 起还有 `title`（显示标题）和 `bg`（特写图 cu_*）。
- 审讯 `statements[]`：
  - `id`、`text`、`lie`、`accept`（证据数组）；
  - `nearMiss`（证据 id → 文本键：出示“沾边”证据时的回应，不扣心烛）；
  - `requires`（前置已拆穿证词 id，满足后该证词才出现）；
  - `onBreak.text`、`onBreak.portrait`、`onBreak.effects`。
- 道具 `use`：见 §8。

### 12.1 `closeups`：特写表（新增）
```json
"closeups": {
  "cu_relief": {
    "title": "立约浮雕",                       // 字面文本，特写窗标题
    "states": [                                 // 自上而下取第一条满足的
      { "req": {"flags": ["int_ysolde_done"]}, "img": "cu_relief_open" },
      { "sanityBelow": 40, "img": "cu_relief_open" },
      { "img": "cu_relief" }                    // 末条无条件＝兜底
    ],
    "overlays": [ { "img": "…", "sanityBelow": 40 } ],          // 可选，透明叠加层，整幅对齐，条件同 states
    "pages": ["…"]                                               // 可选，点按翻页的追加页（本章未用）
  },
  "cu_tapestry": { "states": [ { "sanityBelow": 70, "anim": { "frames": ["cu_tapestry_01","…_04"], "fps": 6, "loop": true } }, { "img": "cu_tapestry_01" } ] }
}
```
- 打开方式：效果 `{ "type": "open", "ui": "closeup", "id": "cu_relief" }`，复用现有 CloseUp 模态窗。`_说明` 这类以 `_` 开头的键不是特写。
- 状态条件：`req` 与 §2 相同（flags / notFlags / items / evidence）。`sanityBelow: N` 表示**打开时**心烛 < N。两者都写时要同时满足。打开时求值一次，窗口打开期间不切换。
- `img`：静态图。`anim`：自动循环的帧序列，不响应点按翻页，`loop:false` 时停在末帧。每个 state 写 `img` 或 `anim` 其中之一。
- `overlays`：满足条件的层按顺序叠在 state 图上，与底图同尺寸，左上对齐。
- 点按翻页只用于 `pages`。没有 pages 时不显示页点，提示文字用“轻触关闭”或不显示。
- 效果顺序约定：hotspot 效果里 `open closeup` 放在 `text` 之前，文本就会显示在特写下方（handle 每条事件都会重新取 this.modal）。若要保持 v1.1 存档里 `once` 的键（`room/hotspot#效果下标`）不变，sanity 效果的下标保持原样（v1.2 已照此排列）。
- 兼容现状的最小接法：chapter.js 中 `puzzleBg[id] = 求值后的 img`、`puzzleTitles[id] = title`，CloseUp 就能显示静态图。动画帧、叠加层和条件求值需要按上面的规则补上。
- 现有谜题特写（puzzles[].bg：cu_crest_door / cu_chest_lock / cu_contract 及 _fine/_seal 自动翻页）保持不变，不并入本表。

### 12.2 `rooms[].fx`：房间场景特效（新增）
```json
"fx": [ { "id": "fx_thread_wriggle", "rect": [433,391,216,216], "fps": 6, "loop": true, "sanityBelow": 40 },
        { "id": "fx_thread_wriggle", "rect": [433,391,216,216], "fps": 6, "loop": true, "req": {"flags": ["cb_cycle_solved"]} } ]
```
- `id`：帧序列前缀，对应文件 `<id>_01…_NN`，与 fx_ink_tendril 一样用 assets.frameImage。`rect`：画布坐标 [x,y,w,h]，帧图缩放进这个矩形。条件写法同 12.1。
- **同一 id 写多条时，任一条满足就绘制一次**（OR），不要重复叠画。只画不拦截点击，画在背景之上、热点高亮与 NPC 立绘之下。
